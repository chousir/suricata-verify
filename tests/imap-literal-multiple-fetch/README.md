# Description

Tests two literal-bearing FETCH responses arriving back to back in the
same batch: `* 1 FETCH (RFC822 {10}...)` immediately followed by
`* 2 FETCH (RFC822 {12}...)`.

This proves `IMAPState.literal_remaining` (and `find_next_literal`'s
scan) reset cleanly once the first literal completes, rather than the
second literal's size or content leaking state from the first. Two
`fileinfo` events are expected, sized 10 and 12 respectively.

# PCAP

Synthetic pcap generated by `gen_pcap.py` (scapy), modeled on
`imap-literal-basic`. Regenerate with `python3 gen_pcap.py`.
