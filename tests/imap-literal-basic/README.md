# Description

Baseline test for the IMAP FETCH literal `{n}` byte-count fix: a single
FETCH response declares a literal of exactly `{16}` octets, and the body
that follows is exactly 16 bytes (`Received: from\r\n`).

The parser must extract exactly the declared 16 octets as the message
literal (surfaced via Suricata's generic file-extraction API as a
`fileinfo` event with `size: 16`), regardless of the `)\r\n` that
immediately follows closing the FETCH response.

# PCAP

Synthetic pcap generated by `gen_pcap.py` (scapy): a full TCP handshake,
an IMAP `LOGIN`, then a `FETCH` request/response pair carrying the
literal, then teardown. Regenerate with `python3 gen_pcap.py`.

Note: IMAP defaults to `enabled: detection-only` in `suricata.yaml`, so
`app-layer.protocols.imap.enabled=yes` must be set for the FETCH parser
(not just protocol detection) to run.
