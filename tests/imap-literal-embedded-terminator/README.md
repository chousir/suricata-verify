# Description

Regression test for the IMAP FETCH literal byte-count bug: the parser
used to scan for the fixed byte sequence `\r\n)\r\n` to find the end of a
FETCH literal, instead of consuming the exact number of octets the
literal declares. Since a literal's octets may legitimately contain
that exact sequence, this desynced the parser.

The FETCH response here declares a `{7}` octet literal whose content is
`A\r\n)\r\nB` - which embeds the old, wrong terminator at position 1. A
correct parser must extract all 7 octets (surfaced as a `fileinfo` event
with `size: 7`); the pre-fix parser would have stopped after the first
byte (`"A"`) and then misparsed the remaining `)\r\nB)\r\n...` bytes as
new response lines, desyncing the rest of the stream.

# PCAP

Synthetic pcap generated by `gen_pcap.py` (scapy), modeled on
`imap-literal-basic`. Regenerate with `python3 gen_pcap.py`.
