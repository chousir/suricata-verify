# Description

One-way / asynchronous coverage for IMAP APPEND: a capture containing only
the client->server direction (client SYN, then a client ACK acking a
phantom SYN-ACK that was never captured, then the LOGIN and APPEND data,
then a client RST -- no server packets at all), run with
`stream.async-oneside=true`. This is the same "one-sided" signature used by
`bug-8629-async-oneside/input.pcap`.

Proves the request-side (client->server) literal extraction path keeps
working correctly even when a whole direction of the flow is entirely
absent: the LOGIN's tagged reply and every other server byte never arrive,
yet the APPEND file still reaches `state: CLOSED` with the correct
`sha256`/`size`, and the parser raises zero anomalies /
`stats.app_layer.error.imap.parser` stays 0.

Also confirms `filestore` actually fires under `stream.async-oneside`
(`fileinfo.stored: true`) -- this isn't automatic just because parsing
works: a *different* one-way mode, `stream.midstream-policy=pass-flow`
(see `imap-literal-midstream-toclient/README.md`), was found to silently
disable all detection including `filestore` while still letting the
parser extract files normally. `stream.async-oneside` does not have that
problem -- verified empirically here, not assumed.

This test exercises the one-way *parsing* path only. It does **not**, and
cannot, observe transaction pruning/freeing -- EVE output has no visibility
into `IMAPState.transactions` or when a transaction is actually freed by
the engine. The regression coverage for that (an AUTH or FILE transaction
correctly reporting progress-complete on the direction that never carries
traffic, which is exactly what a one-sided flow like this one exposed as
broken) is in the Rust unit tests
`test_file_tx_progress_nontraffic_direction_done` and
`test_auth_tx_progress_done_at_creation` in `rust/src/applayerimap/imap.rs`.

# PCAP

Synthetic pcap generated by `gen_pcap.py` (scapy), modeled on
`imap-append-basic/gen_pcap.py` with every server->client packet removed.
Regenerate with `python3 gen_pcap.py`.
