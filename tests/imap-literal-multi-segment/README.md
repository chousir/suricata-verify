# Description

Tests that a FETCH literal split across two TCP segments is reassembled
using the declared `{n}` byte count, not re-derived by scanning content.

The literal is 46 octets; the pcap splits the FETCH response mid-literal
(not on a CRLF boundary) into two TCP segments, so
`IMAPState.literal_remaining` must persist the outstanding octet count
from the first `parse_response()` call to the second. A single
`fileinfo` event with `size: 46` proves the two segments were joined
into one logical literal rather than being treated as two separate (and
wrongly sized) files.

# PCAP

Synthetic pcap generated by `gen_pcap.py` (scapy), modeled on
`imap-literal-basic`. Regenerate with `python3 gen_pcap.py`.
